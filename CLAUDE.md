### Manual fix in 001-baseline.yaml

`generateChangeLog` lost the spatial type metadata. Both `events.location` and `users.location` were emitted as `GEOMETRY(65535)` and were hand-edited to `POINT SRID 4326`. Match nullability to entity (`Event.location` nullable in entity → keep nullable in YAML).

### Known gaps (deliberately left for future changesets, not in baseline)

- **No spatial indexes** on `events.location` / `users.location`. Hibernate `update` never created them. Geographic queries do full table scans today. Add in `002-add-spatial-indexes.yaml` when needed.
- **`role` column is native MySQL `ENUM`**, not VARCHAR. Adding a new `Role` enum value requires an explicit `ALTER TABLE users MODIFY COLUMN role ENUM(...)` changeset. To switch to VARCHAR long-term, add `columnDefinition = "VARCHAR(32)"` on `User.role`.
- **`verification_tokens.user_id` is unique** (1:1 from `@OneToOne`). Means a user can't simultaneously hold an email-verify token AND a password-reset token. Probably intentional — flag if behaviour ever needs to change.
- **`events.start` and `events.end`** use SQL reserved words as column names. Liquibase quotes them automatically but it's fragile.

### Workflow going forward (after prod cutover)

For any entity change:
1. Update the `@Entity` field in Java.
2. Write `00N-description.yaml` in `db/changelog/` with the corresponding `addColumn` / `modifyDataType` / etc.
3. Add an `<include>` line to `db.changelog-master.yaml` (numerical order).
4. Restart app — Liquibase applies, Hibernate validates.
5. Commit both files together.

**Never edit an applied changeset.** Liquibase fails fast on checksum mismatch. Always add a new one.

### Stack notes worth knowing

- Spring Boot 4.0.1 split per-feature autoconfig out of `spring-boot-autoconfigure`. Symptom: dependency on engine alone (e.g. `liquibase-core`) is silently ignored — autoconfig artifact (`spring-boot-liquibase` via `spring-boot-starter-liquibase`) must also be present. Same pattern visible on classpath: `spring-boot-jpa`, `spring-boot-mail`, `spring-boot-security`, `spring-boot-validation` are all separate JARs.
- Liquibase 5.x Maven plugin uses **camelCase** goals: `generateChangeLog`, `changelogSync`, NOT the legacy kebab-case form (`generate-changelog`, `changelog-sync`).
- When all changesets in `DATABASECHANGELOG` are already applied, Liquibase 5 logs nothing at INFO level. To verify it's actually running, add `logging.level.liquibase=INFO` temporarily and look for `liquibase.lockservice` / `liquibase.changelog` lines.
